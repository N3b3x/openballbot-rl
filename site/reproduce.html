Built on OpenBallBot-RL

This study extends OpenBallBot-RL by Achkan Salehi: Reinforcement Learning for Ballbot Navigation in Uneven Terrain, arXiv:2505.18417 (2025), arxiv.org/abs/2505.18417, released under the Apache License 2.0. The MuJoCo ballbot model, the environment and the original PPO pipeline are his; we added the fixes, controllers, studies and this site on top. Please cite the upstream work whenever you use the simulator.

Environment setup

Python 3.9 or newer (pyproject.toml). The study runs on CPU with stock pip install mujoco: the omniwheel contact-frame fix that upstream applies as a MuJoCo patch (tools/mujoco_fix.patch) is re-implemented in ballbot_gym/utils/contact_frame.py.

python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt                       # torch, stable_baselines3, mujoco deps, scipy, matplotlib
pip install -e ballbot_gym/ -e ballbot_rl/
python scripts/setup/verify_installation.py           # sanity check
pytest tests/ -v                                      # unit tests, including the contact-frame fix

The upstream installer bash scripts/setup/install.sh instead builds MuJoCo with the patch (install_mujoco.sh). You do not need it for this study.

Training

One entry point, scripts/study/train_ppo.py. It takes a run name, an observation variant and an env config from configs/env/, and writes outputs/study/runs/<name>/ (final_model.zip, summary.json).

python scripts/study/train_ppo.py --name trk_demo_s0 --variant proprio \
    --env-config configs/env/rob_a.yaml --total-timesteps 10e6 --gamma 0.995 \
    --n-envs 7 --n-steps 512 --batch-size 1792 --seed 0
# fine-tune from a checkpoint, or start a residual-on-LQR policy near zero:
#   --init-from outputs/study/runs/trk_g_s0/final_model.zip
#   --log-std-init -1.5 [--zero-init-actor]

The training queues used for the study are shell scripts that launch several runs in parallel and wait on earlier runs. Read one before running it; they assume the earlier checkpoints exist.

The run name lqr selects the model-based baseline (ballbot_gym/controllers/lqr.py, designed only on the derived model). Run directory names and config names above follow the study log; check outputs/study/runs/ and configs/env/ for what exists on your machine. To render a video: python scripts/study/render_control.py --run <run> --config <config> --out outputs/study/preview/x.mp4 (book terrain: render_book.py).

Design-space tools

python scripts/study/design_space.py sweep                       # analytic sweep -> outputs/study/results/design_sweep.csv
python scripts/study/design_space.py build my_robot --s 1.0      # nominal s=1 (scale); derive model + write a variant model/config (see --help for parameters)
python scripts/study/design_space.py pool my_pool --mode hybrid  # morphology pool for the interleaved controller
python scripts/study/design_constraints.py                       # feasibility margins (traction, torque authority, delay, structure)
python scripts/study/make_design_report.py                       # analytic figure from the sweep

Generated variants go under ballbot_gym/models/variants/. The design rules derived from these tools are in docs/research/design_rules.md.

Config files explained

Each file in configs/env/ is one experiment. It sets the terrain or step, the command distribution, reward weights, pushes, domain randomisation and optional features. Related experiments share a name prefix:

PrefixUse
ctrl_*, lean_*Command-tracking curriculum and the lean-based teacher
rob_*, res_*Robust (domain randomised, pushed) policies and residual-on-LQR policies
climb_*Step-edge training
dz_*One morphology variant each (scale, ball mass, motor, contact angle and so on)
pool_hyb*Interleaved hybrid controller over a pool of designs (hybrid_gate, morph_pool)
book*Book-climbing terrain with proprioceptive, ToF and height-scan observations

Open a file for the exact fields; this table is a guide to the naming only, and the log names the config behind each result.

Expected runtimes

The study log records about 800 environment steps per second per run on CPU (tracking_study_log.md, Open problems). That is a measured rate for one run; parallel runs share cores. Arithmetic from that rate, not separate measurements:

JobStepsTime at 800 steps/s
Morphology run (run_queue_design.sh)5Mabout 1.7 h
Robust or residual run (round 10)10Mabout 3.5 h
Evaluations10 to 30 episodes per cellminutes per policy

A GPU simulator port is listed as future work in the log; it would need the contact-frame fix reimplemented.

Evaluation protocols

  • Tracking. Constant commanded speeds from 0.25 to 1.0 m/s on flat ground; report speed ratio (achieved over commanded), heading error, falls and action rate. Falls are counted by the episode-termination rule in the environment.
  • Pushes. 0.5 m/s drive, one 50 ms push at t = 2 s, forces 0, 10, 20, 30, 40, 50 N, 10 trials per force, any fall counts (eval_push.py). Nominal physics and randomised physics are reported separately.
  • Steps. Raised floor at y = 1 m with a 2 cm bevel on the edge; heights 0 to 3 cm (--heights); success means cross, stop and hold for 2 s. 10 trials per height and speed (0.4 and 0.7 m/s).
  • Designs. Controller re-derived or retrained per variant; speed ratio at fractions of a Froude-scaled speed and pushes in multiples of body weight.
  • Seeds. Held-out evaluation seeds start at 100000 in the original perception study (evaluate.py). Training mostly uses seed 0, so treat single-run differences with caution.

Exact definitions live in the docstrings of the eval_*.py scripts and in the paper's evaluation section.

How to cite

Cite the working paper and the upstream simulator. The paper is a draft; check paper_v2/main.tex for the current title and status.

@unpublished{tadesse2026ballbot,
  author = {Tadesse, Nebiyu},
  title  = {Derived Dynamics Meet Learned Control: Omnidirectional Velocity Tracking for a Small Ballbot},
  note   = {Working draft, simulation study},
  year   = {2026}
}

@article{salehi2025ballbot,
  author  = {Salehi, Achkan},
  title   = {Reinforcement Learning for Ballbot Navigation in Uneven Terrain},
  journal = {arXiv preprint arXiv:2505.18417},
  year    = {2025}
}
